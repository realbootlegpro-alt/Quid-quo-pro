# Project Setup, Dependencies & General Hierarchy

## 1. Purpose (For Hydrogen Bootstrap)
Read this file once during initial workspace setup to verify system binaries, install Python dependencies, create missing persistent folders, build the barebones local Upload & Batch Container UI (Section 7), and understand the Pre-Prod `import_container/` workflow. During regular 3-episode production runs, read **`Persephone.md`** instead so context stays lean.

## 2. System Binary Prerequisites
Verify these are installed and available on `PATH` before running any pipeline script:
1. **Blender 4.5 LTS** (`blender --version` -> must be `4.5.x`; do **not** upgrade to `5.0+` because all `bpy` scripts target `BLENDER_EEVEE_NEXT`, `Action.fcurves`, and Blender 4.x `Principled BSDF` sockets).
   - *Headless Linux note:* `BLENDER_EEVEE_NEXT` requires an OpenGL display context even in `--background` mode. On headless Linux servers/containers where `$DISPLAY` is unset, verify `xvfb-run` is installed and wrap Blender/outer-script calls with `xvfb-run -a` (e.g., `xvfb-run -a python scripts/profile_container.py` or `xvfb-run -a blender --background ...`).
2. **FFmpeg & FFprobe** (`ffmpeg -version`, `ffprobe -version`).

## 3. Outer Python Environment (`requirements.txt`)
Do **not** install third-party packages into Blender's internal Python, and do **not** run `pip install bpy`. Run the outer Python environment separately (`Python 3.11` or `3.12`) and invoke Blender via CLI subprocess (`blender --background --python ...`).

Create and install `requirements.txt` in `project_root/`:
```text
faster-whisper>=1.2.1
av<19
rapidfuzz>=3.0.0
ddgs>=9.0.0
pillow>=10.0.0
httpx>=0.27.0
```
**Critical dependency notes:**
- **`av<19` is mandatory:** `faster-whisper 1.2.1` breaks on `PyAV 19.x` (`metadata_errors` crash). Keep `av<19` pinned.
- **CPU `int8` default:** `align_audio.py` runs `faster-whisper` with `device="cpu"` and `compute_type="int8"` so CUDA 12 / cuDNN 9 are not required for 30-second voiceovers.
- **`ddgs`:** Replaces the deprecated `duckduckgo-search` package.
- **Inside Blender (`bpy`):** Scripts use strictly built-in modules (`bpy`, `bmesh`, `mathutils`, `json`, `os`, `math`).

Keep all project files inside persistent workspace storage—never store models, manifests, or Whisper caches in `/tmp`, as Build containers wipe ephemeral files after ~15 minutes of inactivity.

## 5. Pre-Prod Workflow (MVP)
For the MVP, `sets/` and `animations/` folders are omitted—Block `2.3:1` generates simple procedural stages per `spatial_anchor`, and Block `2.4:1` focuses on rigid props, floating tools, and Shape Keys.

1. Drop recurring `.glb` or `.blend` characters into `import_container/characters/` and common tools/cookware/containers into `import_container/props/` (via the Upload UI or file tree).
2. Run `python scripts/profile_container.py` (prefix with `xvfb-run -a` if on headless Linux with no `$DISPLAY`).
   - Unchanged assets are skipped via `file_hashes.json`.
   - Each new asset gets embedded cameras/lights stripped, flat game-rip shaders converted to lit `Principled BSDF`, its bottom grounded to `z = 0.0` inside an `Empty` wrapper, and a self-contained `<id>_norm.blend` saved in `_index/profiles/`.
   - Characters get `loose_island_count`, `bones[]`, `embedded_animations[]`, `material_slots[]` (`is_closed_shell` flags), and a 2×2 `*_grid.png` with a `0.1m` metric ruler grid.
   - Props get `bottom_z_offset`, `materials[]`, ray-cast `cavity_bounds` (`floor_z`, `rim_z`, `inner_radius`) if hollow, and a 1×2 `*_thumb.png`.

## 6. Build Mode Batching & Bootstrap Checklist
- **Batch size:** Maximum **3 episodes per fresh Build chat** (`concurrency = 1` sequential Blender execution inside the 4GB sandbox). Open a fresh Build chat after every 3-episode batch.
- **Bootstrap command sequence for Hydrogen:**
  1. Check `blender --version` (`4.5.x`), `ffmpeg -version`, and `which xvfb-run` (if on Linux without `DISPLAY`).
  2. Install `pip install -r requirements.txt`.
  3. Ensure `import_container/characters/`, `import_container/props/`, `import_container/_index/profiles/`, and `batches/` exist.
  4. Build the barebones Upload & Batch Container web UI defined in Section 7.
  5. If assets are present in `import_container/`, run `python scripts/profile_container.py` (with `xvfb-run -a` if headless Linux) and verify `_index/asset_catalog.json`.

## 7. Barebones Upload & Batch Container UI (Build App Spec)
Build a **minimal, barebones single-page file manager** (React + Node.js/Express with `multer` or streaming uploads, plain minimal styling) strictly for managing persistent folders and triggering the Pre-Prod profiler:

* **Panel 1 — Import Container (`import_container/`):**
  * Toggle between `characters/` and `props/`.
  * Drag-and-drop / multi-file upload (`.glb`, `.blend`, up to 100 MB per file) saving straight into `import_container/<category>/` (never `/tmp`).
  * Clean list of files showing name, size, `"Profiled"` vs `"Unprofiled"` status (checked against `_index/asset_catalog.json`), click-to-view preview image (`_grid.png` / `_thumb.png`), and a **Delete** button (deletes the source file).
  * One **"Run Profiler"** button that executes `profile_container.py` (auto-wrapping with `xvfb-run -a` on headless Linux when `$DISPLAY` is unset) and displays plain stdout logs + refreshes status.
* **Panel 2 — Batches (`batches/`):**
  * Create and delete batch folders (`batch_001`) and episode subfolders (`ep_01_souffle`, automatically initializing `0_input/`).
  * Upload/replace/delete `storyboard.json` and `narration.mp3`/`.wav` inside `0_input/`.
  * List files inside `5_output/` (`_master.mp4`, `.srt`, `_cues.txt`) with 1-click **Download** buttons once Persephone finishes.
* **Strict Anti-Bloat Rules (Do NOT Add):**
  * No database, no login/auth, no charts or analytics cards, no in-browser Three.js 3D viewer, and **no Gemini API calls inside the app** (all AI execution stays inside Build chat).
